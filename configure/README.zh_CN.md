# 离线工牌配置

编辑 `page.html`、`profile-core.js` 和 `app.js`，在仓库根目录运行 `python tools/build_config_page.py`。CMake 会在输入变化后执行同一生成器。`index.html` 与 `main/assets/configure.html.gz` 分别为独立网页和固件内嵌页面，不依赖 CDN、外部 API 或云服务。

USB 与热点共用协议 2。连接后读取已保存的身份资料、配色、图标、头像、二维码、Wi-Fi 状态和不含秘密的 Muse 配置状态。不会回传 Wi-Fi 密码；仅同一网络支持密码留空保留。支持开放网络和密码为 8–63 个 UTF-8 字节的个人网络，硬件支持 2.4 GHz Wi-Fi。

热点配置：系统设置 → OK 网络设置 → OK 开启热点。连接屏幕显示的 WPA2 热点，输入本次生成的随机密码，打开 `http://192.168.4.1`。服务器仅允许通过热点网卡访问，拒绝外部 Origin，API 需要本次会话的请求头令牌。十分钟没有 HTTP 请求会关闭热点。USB 与 HTTP 共用双存档区、写入会话归属和超时控制。Wi-Fi 凭证保存在独立 NVS 数据项，不进入资料导出。

Muse 配置接受设备主人的 SDK Token 和可选 IPv4 HTTP CONNECT 代理。Token 只写不读：协议只返回 `tokenSet`，不会返回原值；Token 留空会保留已有值。更换 Token 会清除旧 Muse 账号配对，只修改或清空代理会保留配对。Muse 小程序拥有会话时拒绝配置写入。

品牌文字栅格为 148 × 44，图标为 32 × 32，头像为 72 × 88，资料卡为 208 × 148 RGB565。二维码在本机识别，以整数像素模块和留白重新生成，再次识别并对比原始字节后才接受。192 × 192 区域内不能保证每模块至少两个像素的复杂二维码会被拒绝。二维码始终使用黑白对比，不随主题变色；仍需用手机在实物屏幕上验证微信扫码。

## 第三方库

- jsQR 1.4.0 来自官方 npm 包，上游 https://github.com/cozmo/jsQR，Apache-2.0；见 `vendor/jsQR.LICENSE`。
- Project Nayuki 二维码生成器，上游 https://github.com/nayuki/QR-Code-generator/blob/master/typescript-javascript/qrcodegen.ts，获取日期 2026-09-15，MIT；见 `vendor/qrcodegen.LICENSE`。使用 TypeScript 5.9.3 编译，两个库均使用 Terser 5.44.0 压缩，并内嵌到页面。
- `assets/images/cyber-badge/test-qr.bin` 编码的是公开测试地址 `https://example.com/test-contact`，不含真实联系方式。

## 一键亮码

1.3.1 起，工牌首页按下键直接显示已保存二维码；再按下键、OK 或长按 OK 返回工牌。从菜单进入二维码时，以上返回操作回到菜单。小游戏从员工终端进入。

## 附近网络列表（1.3.2）

连接后自动扫描，也可点击“刷新列表”。列表最多显示信号最强的 16 个网络，按 SSID 与加密方式合并重复热点。每次扫描最多读取 64 条原始记录；隐藏 SSID 不列出，可手动填写。WEP、仅 WPA 和企业网络暂不支持选择。选择不同网络时清除尚未提交的密码，避免将密码填到其他网络。

扫描由工牌执行，USB 与 HTTP 共用 `wifi_scan` / `wifi_scan_results` 接口。网络工作任务执行扫描，网页异步轮询结果，设备按键和协议服务继续工作。扫描失败或连接忙时保留原列表并提示刷新，不自动切换或保存网络。

## 五张工牌（1.6.0）

配置页支持保存五张独立工牌。在工牌库选择位置，分别设置姓名、品牌、配色、头像和二维码，然后保存。编辑或保存另一张工牌不会切换硬件显示；点击**显示这张工牌**才会切换。页面明确区分“正在编辑”和“当前显示”，连接时可读取已保存资料。清空仅影响选中的一张。Wi-Fi 设置由设备共用。

工牌首页**双击 OK**打开工牌列表；上下键选择，OK 切换显示，长按 OK 返回。空白位置标记为“未设置”，在硬件列表中不能启用。单击 OK 仍打开终端，下键仍显示当前工牌的二维码。重启后记住上次显示的工牌。升级时原有资料保留在第 1 张。

USB 和热点配置均支持五张工牌。升级后请刷新已打开的配置页。写入明确指定工牌，并核对读取时的版本；如果其他连接已修改这张工牌，需要重新读取后再保存。保存当前显示的工牌会更新屏幕，保存其他工牌则保持当前身份和二维码。

### 多工牌协议

工牌 ID 从零开始（`badge: 0` 至 `4`）。`info` 和 `read` 可传入 `badge` 指定工牌，省略时读取当前显示工牌。`info` 返回 `badge`、`badgeRevision`、`activeBadge`、`badgeCount`，以及包含各位置 ID、版本、是否设置、姓名和品牌的 `badges` 数组。`badges` 操作仅返回工牌目录和运行时版本。

五张工牌固件的 `begin` 和 `clear` 必须显式传入 `badge`。同时传入上次读取的 `baseRevision`，可拒绝过期写入。`begin` 之后的 `chunk`/`commit` 始终绑定该工牌和事务所有者，切换显示不会重定向上传。`badge_select` 携带 `badge` 可切换并记住显示位置。上传未结束或界面尚未释放上一份图片引用时，切换及下一次写入会被拒绝，当前操作完成后可重试。每张工牌的版本独立；`revision` 仍是运行期间的界面刷新计数。

1.7.0 起，当前工牌配色也会应用到内置游戏。保存当前工牌可刷新正在运行的游戏；保存其他位置不会改变当前主题，需要切换显示该工牌才会应用。

## 姓名换行和工牌序号（1.7.1）

姓名自动换行，最多两行，英文优先按空格分词。较长姓名会缩小字号，最小字号仍超出两行时才显示省略号；完整姓名保留在资料中。保存图片的姓名区域仍为 112 × 32，不改变存储格式及其他字段。旧工牌需要在新版配置页读取并保存一次，重新生成姓名图片。首页和预览使用 `1/5`，工牌列表行号为 1–5，均不补零。

## 资料区域留白（1.9.0）

姓名、部门与职位的显示区域同步调整为固件新坐标，保留原有裁剪来源和资料格式。已有工牌无需重新保存即可在硬件上看到新间距；刷新配置页查看同步后的预览。

## 公司名称排版（2.6.31）

公司名称使用内嵌 Noto Sans SC 700 的拉丁比例字形，中文沿用现有回退字体。配置页等比例调整字号，在 148 像素品牌图片内预留 144 像素安全宽度，不横向拉伸或挤压字符。已保存的工牌图片需要重新保存该工牌才会更新。USB 和热点配置页共用该绘制逻辑。
