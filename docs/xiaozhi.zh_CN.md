# 小智小程序

2.1.0 版本集成 [Folo AI Passport XiaoZhi](https://github.com/FoloToy/folo-ai-passport-xiaozhi)
的语音对话协议，参考提交 `d24fce080d86d7cc642f71585f6efde40fb99104`（上游小智 2.4.2）。
MIT 许可证及上游声明保留在 `assets/xiaozhi/`。

## 2.6.0 当前入口

小智已从“小程序”移至 **设置 → 小智 AI**，选择开始对话自动连接，首页长按上键仍可启动。回复音量共用原有保存值。可选后台本地唤醒与自定义训练模型导入见[后台唤醒](xiaozhi-background.zh_CN.md)。下面旧版本章节描述当时行为，入口与本地唤醒能力以本节为准。

## 共用设置与操作

从员工终端进入“小程序”，选择“小智对话”。Wi-Fi、热点引导、亮度、工牌资料、主题与返回导航均由工牌系统管理。
不引入小智独立设置页或第二套 Wi-Fi 管理器。顶部与首页完全一致，显示 AI Passport、Wi-Fi 和电量百分比。

- 按 OK 连接。需要激活时，打开 `xiaozhi.me`，登录控制台并使用工牌显示的激活码添加设备；绑定完成后按 OK 重试。
- 2.1.3 按一次 OK 连接并开始连续对话，使用服务端 `auto` 模式判断说话结束，无需手动发送。回复播放完毕后自动重新开启聆听。
- 聆听时按 OK 暂停，再按 OK 继续；回答时按 OK 打断，经过短暂的回声 / 尾包保护后重新聆听。每轮录音仍有 30 秒上限。
- 当前对话页和系统小智音量页的上下键每次调节 5 个百分点，在 0～100 上下限停止。原有保存值（包括语音/API 设置的非五倍数精确百分比）保留，不作四舍五入。2.1.4 引入的音量偏好仍跨重新进入和重启恢复，0 为静音，继续共用工牌音频硬件。
- 长按 OK 使用系统“上一页 / 首页 / 继续”选择器。
- 退出时关闭网络连接、释放语音资源。用户开始对话后，聆听阶段会上传麦克风音频，直到暂停、断开或退出。

当前采用用户启动后的连续半双工对话：回复时停止收音，回复后继续聆听；播放期间用 OK 打断，不提供全双工语音抢话或本地唤醒词。小程序不引入独立 OTA 固件替换、额外板级驱动及上游设置界面。
服务发现接口只用于取得服务地址和激活信息，返回的固件下载指令不会执行。云端对话需要用户绑定账号，且小智服务可达。

## 2.1.4 沉浸式对话与音量记忆

对话页采用中心声纹、聆听 / 思考 / 回答状态和无卡片字幕舞台，沿用当前工牌配色与统一顶部。
声纹由实际收音或解码音频的强度驱动，只刷新中间的 41 × 35 像素区域；静态画面不重绘，不新增常驻动画。
字幕每屏四行，思考时聚焦识别到的输入，回答时聚焦小智当前回复。
超出区域时每四秒按整行翻页，并重叠一行；聆听或暂停期间，翻完一方的文字后轮换显示另一方。
新字幕从第一页显示，连接错误和激活提示优先于旧字幕。
保留最近输入（最多 255 个 UTF-8 字节）及当前回复句子（最多 511 字节），不保存无限历史。

音量按键只更新原子请求，音频工作线程即使在待机也会应用音量。
使用现有 `xiaozhi` NVS 命名空间中的 `volume` 键保存 0～100；未保存时继承共享音频硬件的当前值。
连续调节后等待一秒，选择无音频工作或一轮播放排空的安全时机提交；退出时补存最新值。
保存失败保留待保存状态、三秒后重试并记录错误。播放中不写 Flash，避免影响声音连续性。
立即断电且尚未提交的最后一次调整可能丢失；正常退出和提交后的重启均可恢复。

2.1.3 在建立 MQTT / TLS 连接前预留同一块编解码工作区，录音和播放时交替初始化，
调用现有 `esp_audio_codec` 库导出的标准 Opus 原地初始化接口，避免每轮分配连续内存，不额外链接另一份编解码器。

## 实现说明

### 2.1.1 待机策略

待机策略作用于小智小程序，仍以工牌的共享设置为准。

| 项目 | 行为 |
| --- | --- |
| 屏幕 | 无按键、无活跃对话 60 秒后：背光 0、ST7789 Sleep In、停止 LVGL 心跳定时器并暂停 LVGL 任务。 |
| CPU | ESP-IDF 自动电源管理，最高 160 MHz、最低 40 MHz；开启 tickless idle，息屏时允许自动 light sleep。亮屏页面持有性能锁。 |
| Wi-Fi | 站点侦听间隔 20；小智空闲使用 MAX modem sleep，连接、录音、回答时使用 NONE，退出恢复共享的 MIN 策略。 |
| 按键 | 共享扫描周期 50 ms，去抖 1 个采样周期；吞掉完整的首次唤醒手势，包括延迟单击和长按。 |
| 音频 | 15 秒无录音/播放后休眠 ES8311、停止 I2S TX/RX，同时关闭麦克风输入。亮屏唤醒恢复原采样格式、麦克风增益和共享音量；若恢复失败，下次音频操作会重试。 |
| 后台 | 息屏跳过状态栏、电量及资料界面刷新和小智绘制；USB 空闲轮询降至每秒一次，不增加周期性 heap 打印。 |
| 唤醒 | 恢复屏幕、LVGL 任务/定时器与保存的亮度；亮度为 0 时兜底 80%。退出前先恢复显示，之后才允许删除页面。 |

当前固定版本的 LVGL 在计时器被禁用后，会返回 1 ms 的轮询间隔，因此仅调用
`lvgl_port_stop()` 不足以省电。BSP 持有 LVGL 锁后，同时暂停已记录的 LVGL 任务，
恢复也在同一把锁下完成。音频休眠失败保持可重试，不误报为休眠成功。

硬件定义为 `BSP_I2S_PA_CTRL=-1`，没有 MCU 可控制的功放电源开关；支持 codec 休眠，
不能切断功放供电。连接 USB 时，ESP-IDF 持有禁止自动轻睡眠的锁，以保留串口配置和烧录；
自动轻睡眠及电流测量需要使用电池运行。配置热点开启时也可能限制 Wi-Fi 节能。
侦听间隔 20 可能增加约 2～3 秒空闲消息延迟，具体取决于路由器，不保证端到端时延。
4～6 mA 的节电幅度需用电流表测量。参考
[Espressif Wi-Fi 低功耗说明](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c3/api-guides/low-power-mode/low-power-mode-wifi.html)。

### 协议与内存

`xiaozhi_app.cc` 适配上游服务发现、WebSocket v1/v2/v3 和 MQTT/UDP 协议。
UDP 音频使用 AES-CTR，并拒绝旧序列号。TLS 使用 ESP-IDF 证书包。
远程音频包、控制消息组装、会话标识及服务地址均有长度限制。
不受支持的 WebSocket 分片消息会关闭连接，等待明确重试。2.4.9 的 MCP 支持读取状态、打开小程序、搜索和播放音效、显示二维码、切换工牌与调整现有亮度设置。
接口、生命周期与验证见[小智设备控制](assistant-control.zh_CN.md)。不能替换固件；切换小程序会结束对话。

单个后台任务负责网络、NVS 和音频；按键仅更新原子变量。
MQTT 回调只把有界控制消息放入有界队列。UI 访问持有 LVGL 锁。
退出先等待生产任务结束，超时保留页面。针对没有 PSRAM 的 C3，Opus 编码器和解码器在同一工作区交替初始化。
语音任务为 SILK 编码预留 28 KiB 栈；UI 内存池为 32 KiB，所有已有页面与返回浮层的生命周期测试使用相同限制。
TLS 按需分配收发缓冲，保留证书验证和 16 KiB 接收记录；发送分片为 2 KiB，可容纳受限长度的 MQTT 控制消息及最长 1,516 字节的 WebSocket 音频帧。
Wi-Fi 沿用上游 C3 的接收预算（3 个静态、6 个动态缓冲和 3 帧 BA 窗口），
使用动态管理帧缓冲并将接收优化代码放回 Flash，释放内部 RAM；仍由同一个工牌网络管理器管理。
音效钥匙扣与小智共用 `esp_audio_codec` 2.5.0；原 libopus 源码保留给离线工具，设备链接时排除，避免重复符号。
两款应用仍使用原来的 16 kHz 单声道音频格式。

`font_xiaozhi_14.c` 提供 7,540 个 ASCII/GB2312 字符，使用 Noto Sans SC 生成，14 像素、1 位像素。
182,101 字节的字形位图保存在 Flash。字符集以外的生僻字可能显示缺字替代符。

原应用、音效及五张工牌的分区地址不变。升级保留 NVS 与工牌分区。
刷过其他应用的设备，必须先核验真实分区表、备份不兼容的数据，再安装工牌布局。
工牌分区缺失或映射失败时，现在安全返回空资料，不再访问未初始化的存储槽位。

## 2.1.2 回复播放

收到的 Opus 音频先进入 4 KiB 变长队列，仅在回答时分配，开始录音前释放。
默认缓存约 180 ms 后起播；较短回复在收到结束消息或等待 300 ms 后播放。
每轮先批量收包，再写入 I2S；UDP 接收邮箱扩为 16 包。
回复结束同时等待网络安静期和播放队列排空，保留末尾音节。

WebSocket 接收区只在使用 WebSocket 时分配，MQTT 模式节省约 2 KiB。
优先分配解码器，再分配压缩音频队列，避免切碎无 PSRAM 工牌上 Opus 所需的大块空闲内存。
屏幕每次分块传输从 20 行调整为 10 行，额外释放 4,800 字节；字幕快照使用界面内存池的剩余空间。
这些调整为解码器保留足够的连续内存，实测也覆盖共享热点开启的情况；仅检查空闲总量并不足以判断能否分配成功。

音频线程只提交快照副本，不等待屏幕锁；LVGL 的 100 ms 定时器在界面线程应用最新快照，
退出页面时删除，息屏时随 LVGL 一起暂停。背景未变化时不触发重绘；
只有音量变化才写入音频芯片。活跃对话循环延时为 1 ms，空闲仍为 50 ms。
保留 60 秒息屏，以及对话时 Wi-Fi / CPU 的性能策略。
缓冲会增加少量起播延迟，用于吸收网络抖动，不能消除长时间断网造成的停顿。

## 2.1.7 声纹主视觉与逐字字幕

声纹成为主视觉，用 13 根中间高、两侧低的细柱直接响应实际收音、播放 PCM 的强弱，
去掉拖延响应的缓动、交织线条和多层光效。它是声音驱动的图形，不是频谱或生物识别声纹。
只重绘发生变化的 4 × 144 像素窄条，每次音量更新最多 7,488 像素，音量不变时不重绘。
收听、播放时数据发布最小间隔由 200 ms 缩短为 50 ms，在输入音量测量后、输出写入后直接提交；
收听、思考、回复状态的 UI 消费间隔为 50 ms，其余状态为 100 ms。
以上是调度间隔，不代表端到端延迟保证，仍受音频分帧和任务调度影响。
无空闲常驻动画，息屏继续停用 LVGL。

字幕缩为两行。识别输入按本地时钟逐个完整 UTF-8 字符显示；回复字幕根据已经写入音频输出的 PCM 时长渐显，

非 ASCII 字符按 150 ms、ASCII 字符按 80 ms 估算，属于近似跟随，不能保证逐字精准同步。
播放时长未推进时不会越过对应字幕进度；播放结束后剩余文字由本地时钟继续展开。
新句替换上一句，超过两行按整行上移，显示最近两行，不作为完整聊天记录。
音量记忆、开始 / 暂停、共享顶部及息屏行为不变；绘制仍在 LVGL 线程执行，不阻塞音频线程等待 UI。

逐字字幕固定左侧起点，避免新增字符时整行左右移动。

## 2.1.8 字幕时序修正

## 短时连接复用（2.6.4）

返回工牌或设置后，健康的 MQTT/TLS 连接最多保留 120 秒；音频缓冲区、编解码器、
28 KiB 语音任务栈、UDP 套接字及页面均会释放。再次进入时，在原连接上重新进行
hello 握手，取得新的语音会话和 UDP 参数，不承诺保留聊天历史。
MQTT 客户端任务负责心跳；后台收到的消息直接丢弃，不显示字幕、不执行工具调用。
WebSocket 连接仍在退出时关闭。

进入其他小程序前会释放保留的连接。连接断开、剩余堆内存低于 48 KiB 或保留时间
到期时也会释放；清理在导航任务中执行，不持有 LVGL 锁。Wi-Fi 仍由整个系统共用。
通过校验的服务配置仅在内存中缓存十分钟；缓存连接失败后，重新获取服务配置一次。
需要激活的结果不缓存，服务凭据不会写入工牌资料或 NVS。

可选的 `BADGE_XIAOZHI_REUSE_PROBE` 检查真实服务握手、重复进入、与后台唤醒共存、
进入小程序时释放、断线和超时释放。测试禁止上传麦克风音频，发行固件必须关闭此开关。

已连接工牌上的验证：六次真实服务握手通过，其中两次复用握手从语音任务就绪到复用
完成分别为 207 / 477 毫秒；切换音效库释放、主动模拟 MQTT 断开，以及实际等待
120 秒到期释放均通过。服务配置只获取一次；保留连接时后台唤醒正常，剩余堆内存
约 61 KiB，音量设置保持不变。本测试未覆盖真实说话识别、复用后的语音播放及长期

## 2.6.22 连接就绪与摇卦交接

固定方法列表直接作为 JSON 输出，不再临时展开整棵 cJSON 对象树；主机测试解析实际输出并检查 16 个方法及大小上限。方法列表只描述固定功能，完整卦象通过 `self.yao.get` 返回，不再拼入工具说明。页面发起的首轮解读中，省略编号会返回页面确认的完整快照；明确指定其他编号会报错。完整卦名、本卦与之卦以及六条爻辞保持完整，同时避免服务器缓存旧卦象。

### 已复现的问题与验证

在该设备上，旧版附带卦象的方法列表为 8,396 字节，发送时反复出现 socket 错误 104（对端重置连接）。尚未独立确认上游的精确报文大小限制。新版固定列表为 6,809 字节。第一句回复还暴露了内存碎片问题：总空闲 54,624 字节，最大连续块只有 22,528 字节，小于共用编码/解码缓冲区需要的 24,524 字节。单独保留音频区仍会遇到序列化峰值，因此方法列表改为固定原始 JSON，并使用一次分配的 8KB 输出缓冲区，避免输出时自动扩容。

修复后真机完成了两次摇卦解读交接，第二次复用了连接。两次 `self.yao.get` 均包含完整卦名和双方各六条爻辞；播放检查分别解码 134,400 和 129,600 个采样后返回相同卦象。这是有限时长的播放检查，不代表播放完两段完整长篇解读。主机还在 1KB 临时分配预算下构建方法列表，并校验输出 JSON。

三次普通进入也通过了每次八秒的聆听连接检查，包括两次 MQTT 连接复用，全程仅注册一次方法列表。测试上传的是合成静音，没有上传麦克风录音。
