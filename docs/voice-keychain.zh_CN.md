# 音效钥匙扣集成 — 1.8.0

作为工牌的第二款游戏，集成 [Shinku-Chen 的 feature/voice-keychain 分支](https://github.com/Shinku-Chen/ai-passport/tree/feature/voice-keychain)，提交 `71c45cabc1b2f3b73b4929d71cafd926ccbb11f5`。保留全部 24 个分类、818 段音效，未重新编码。原工牌主系统与敲木鱼继续保留。

## 操作与主题

- 小游戏列表 → 音效钥匙扣。上下选择，OK 进入或播放；再次播放会打断当前音效。
- 长按 OK 返回上一级；在分类首页长按 OK 返回小游戏列表。
- 长按上键打开音量设置，上键增大、下键减小，每次 5%；OK 返回。长按下键停止播放。
- 默认音量 40%，保存到独立 NVS 命名空间 `voice_key_v1`。变更在播放器空闲且间隔达到三秒时保存，退出时也会保存；损坏的 NVS 不会被自动擦除。
- 背景、面板、强调色、主文字、次文字均跟随当前工牌，支持游戏中同步资料更新。选中的长标题滚动，未选中的长标题显示省略号。顶部电量沿用小字号，无 BAT 前缀。

## 实现结构

`game_registry.c` 增加 `voice-keychain`。可选的 `back` 回调处理游戏内部多级页面，现有生命周期负责进入、启动、停止和删除游戏。不启动上游独占开机流程、USB 服务或自动休眠控制器。

`voice_navigation.c` 是独立于硬件的菜单状态机；`voice_ui.c` 使用共享主题及六行复用列表。UI 与定时器访问遵循 LVGL 锁。单个后台任务处理流式读取、定点 Opus 解码、PCM 输出、电量读取及 NVS。长度为 1 的请求队列加请求序号取消旧播放，不累积任务、不逐包分配内存。播放器任务栈为 16 KB。退出先取消并等待任务结束，再删除资源和 UI 定时器；等待超时保留页面，允许重试。

音频为 16 kHz 单声道 Opus，使用两字节小端数据包长度前缀。数据包最大 1500 字节，单次解码最多 960 个采样。两段原始音效分区组成连续逻辑流，跨分区读取有明确边界检查，无文件系统挂载或自动格式化。

| 区域 | 地址 | 大小 |
| --- | --- | --- |
| 应用程序 | 0x10000 | 0x200000 |
| 音效主区 | 0x210000 | 0x480000 |
| 第 2–5 张工牌，保留 | 0x690000 | 0xC0000 |
| 音效尾区 | 0x750000 | 0x80000 |
| 第 1 张工牌，保留 | 0x7D0000 | 0x30000 |

NVS、PHY 地址不变。打包工具检查路径、长度、数据包边界及容量，生成带 CRC 的头、索引和两段镜像。实际音频为 4,904,252 字节。`verify_firmware.py` 校验五个刷写镜像，并调用本产品的音效资源校验器。两段音效镜像合计 5 MB，空闲部分填充 0xFF。

## 编译与保留资料安装

按根目录 README 使用 ESP-IDF 5.5.3 编译。CMake 自动从已提交资源生成音效镜像和索引。已包含生成的 Noto Sans SC 字库；重新生成需要 Pillow 和 OFL 原字体。第三方 libopus 保留 COPYING；音效来源单独记录于 `assets/audio/voice-keychain/SOURCE.txt`。

```bash
python tools/flash_badge.py --port COM6 --backup-dir /private/new-backup-directory
```

安装工具校验编译产物、分块创建私有整机备份（每块 1 MB，设备 MD5 校验，单块读取最多尝试三次）、检查现有资料地址和空闲空间，只分段写入五个镜像，再逐字节核对两段工牌存储。备份包含私人数据，必须留在源码及交付目录之外。先释放 USB 配置连接。已有资料的工牌不要刷合并镜像：其填充会覆盖 NVS 和第 2–5 张工牌。合并镜像只用于空白设备。

## 验证记录，2026-09-15

| 字段 | 结果 |
| --- | --- |
| Build | PASS — Windows 原生 ESP-IDF 编译，应用可放入 2 MB 分区，合并镜像及音效资源校验 |
| Host tests | PASS — 全部 818 个选择项、损坏/截断包、跨分区边界、确定性打包 CRC、现有仓库和主机门禁、四套配色渲染、100 次语音/木鱼 UI 切换 |
| Device tests | PASS — 1.8.0 分段安装、五张工牌存储逐字节一致、正常启动并识别两款游戏、当前工牌和 Wi-Fi 配置保留，Wi-Fi 已连接 |
| Unverified | 实体按键、实际播放及音质、设备解码任务栈余量、反复进出游戏、长时间运行 |

相同的定点解码器在主机上成功解码全部 138,458 个包，共 44,306,560 个采样。实际 LVGL 9.5.0 在 40 KB 内存池中渲染，峰值占用 20,448 字节；100 次语音/木鱼 UI 切换后剩余 17,072 字节，测试前为 16,944 字节。这验证 UI 分配行为，不代表 ESP32 全部堆内存或实机音频时序。WSL 执行静态门禁，Windows 原生执行对应的编译、合并、校验；未声称运行过单次 POSIX 完整门禁。

### 旧版尾部残留

部分旧设备在未使用的应用尾部有历史残留字节。默认安装会拒绝覆盖。核对私有备份后，可以为已知的 1.7.1 工牌加入 `--reuse-unused-tail`；工具仍强制核对旧分区布局、程序版本标记、段长度、校验和及 SHA-256，并确认程序完全位于新音效区域之前。未知应用或越界/损坏镜像会被拒绝。此次迁移已确认旧程序为 1,511,664 字节，结束于 0x1810F0；两段音效区均在当前程序及工牌存储之外。

### 本机安装结果

应用 1,750,832 字节，合并镜像 8,192,000 字节。五段写入均通过设备哈希校验。整机私有备份完成后再次校验旧程序、分区表及工牌存档与备份一致，再进行分段写入。写入后回读两段工牌分区，全部字节保持一致。启动报告两款游戏，按键、电量、存储初始化正常，资料及 USB 服务均返回 ESP_OK。USB 回读五张工牌、当前显示和 Wi-Fi 配置与安装前一致，Wi-Fi 已连接。最后已关闭串口。

合并镜像 SHA-256：`5daff14195cb9c16249ca8a9eedcc0d6adbef0f9280b0ba9192406c800f06fc7`。

## 2.1.0 共用编解码库

音效钥匙扣和小智现在共用乐鑫 `esp_audio_codec` 的 Opus 解码器。音效数据、包长度限制及音量保存方式保持不变。原 libopus 解码器保留给离线工具，不再参与固件链接。详见[小智验证说明](xiaozhi.zh_CN.md)。
