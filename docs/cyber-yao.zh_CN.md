# 赛博摇卦与小智解读

2.6.20 增加适配工牌主题的六爻小程序和两个 MCP 方法。
核心来自 [CyberYAO](https://github.com/XadillaX/CyberYAO/tree/3c4780feea04737e6e59b6e1849e591710e6656c)，
保留其 [MIT 许可](../assets/cyberyao/LICENSE)。未引入上游字体、图片、音频、
Recovery 固件、独立网络管理或待机页面。

## 操作

从小程序列表打开「赛博摇卦」，心中想好所问，按六次 OK，每次投掷三枚铜钱，
六爻自下而上生成。完成后显示本卦、之卦并标记动爻。2.6.21 起支持滚动浏览本卦和之卦各自的完整卦辞、六条爻辞，以及乾坤的用九／用六，保留主读、参读标记；无动爻时不重复显示同一卦。
上下键滚动阅读；长按下键重新开始。应用出口长按 OK，存在不同去向时选择小程序、工牌或继续；安全的单工牌入口直接返回。详见[返回导航](setup-navigation.zh_CN.md)。

在结果页按 OK，请小智解读。需要系统 Wi-Fi 已连接、小智服务已激活。
进入对话时保留本次结果的完整快照，由 `self.yao.get` 查询返回，
包括结果编号、本卦、之卦、六爻、动爻、主读规则以及两卦各自完整的卦辞、六条爻辞和特殊用辞。
本卦、之卦的 `name` 和选读引用的 `hexagram_name` 使用完整卦名（例如“水火既济”“水山蹇”“乾为天”）；`short_name` 仅保留原数据简称，`number` 为卦序。
从 2.6.27 起，完整原文仅作解读依据，默认直接用白话给出结论、趋势、注意事项和建议，结合主读和动爻综合解释，不先朗读原文或逐爻翻译。只有用户明确要求原文或逐爻详解时才展开；无动爻不重复解读。此规则同时用于页面解读和语音起卦、查询，实际措辞由云端模型生成。
方法发现成功后，通过正常语音输入通道发送固定合成语音“请查询刚才摇出的卦象，并根据原文解读”。
这段约 4.7 秒、约 5.3 KB 的 Opus 音频直接上传，不在本地播放，也不录制麦克风；
使用 manual 模式并在发送完成后 stop，小智通过查询方法读取原记录。
云端的 `listen/detect` 不接受长文本，短触发文本实测也不回复，因此不使用该通道传递请求。
界面提示显示本次本卦和之卦的名称。
固件在首次解读轮次拒绝重新起卦的方法调用，也不经过首页。小智退出弹窗中选择返回卦象，会回到保留的结果；活跃会话默认选继续。
没有说明问题时，小智会在后续对话中询问。原文与 AI 解读分开；
本程序没有另一个预先编写的个性化批文库。

## 所问事项、时间与自动定位

若结果和对话中均没有明确的所问事项，小智先询问具体事情和必要背景，等待补充后再解读，不自行假定问题。补充事项沿用当前卦象，不重新起卦。

从 2.6.29 起不再手填地区或经度。Wi-Fi 获得 IP 且没有有效缓存时标记定位任务；进入起卦程序复用一小时内成功获取的地区和经度，不取消正在执行的请求。网络任务在完成系统校时、屏幕点亮、无音频程序占用且内存允许时查询公网 IP 的近似城市和经度，先用 ipwho.is，失败再用 ip-api.com。正在播放或息屏时延后；后台语音唤醒监听不再阻止定位，定位也不唤醒屏幕。失败后每 15 秒自动重试；有效缓存期间断线重连或换网不重复定位。定位与起卦互不等待。

地区和经度从获取成功开始在内存中缓存一小时，使用不受校时影响的单调计时；重启失效，不读取旧版手填配置，也不写入闪存。缓存不包括时间值：系统时钟持续走时，每次成卦根据当时 UTC、经度及当天均时差重新计算真太阳时。缓存过期后在资源允许时自动刷新。超时、接口异常、字段缺失、任务创建失败或内存不足时不阻塞起卦，没有可用位置就用已有系统时间、不校准真太阳时，不要求补填地区。起卦页持续显示准备定位、定位中、等待重试、已校准或等待 Wi-Fi；配置页也显示同一状态。

手动起卦在第六次投掷完成时保存 `cast_time`，语音起卦在成卦时保存；包括 UTC、北京时间（明确标注 UTC+8）及当时可用的近似地区、经度、真太阳时和均时差。若手动成卦时定位尚未返回，页面会在定位成功后为这条结果补入位置，但仍使用原成卦时间计算；交给小智前还会再检查一次。`current_time` 另提供查询时刻，不代替起卦时刻。

真太阳时使用 [NOAA 天文近似公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)：UTC 加经度每度 4 分钟，再加当天均时差，处理跨日与闰年。结果是当地太阳时，不是 UTC 时间戳；不会更改系统时钟、提醒或顶部时间。未增加干支历法或纳甲排盘，仍以原项目的卦辞、爻辞、动爻规则解读。

设备时间不可信时返回 `clock_valid=false`，位置不可用时返回 `location_set=false`；未校时不编造时间相关推断，未定位不阻止解读。网络位置标记 `network_ip_approx`，不能当成精确定位。定位服务收到设备公网 IP；原文、事项与时间地区发送给当前小智服务，最终回复由云端模型生成。

## 方法与保存

- `self.yao.cast(request_id, question?)`：一次完成六爻，直接返回结构化结果，
  保持对话。请求标识允许 1～48 个英文字母、数字、下划线或短横线；
  所问最多 96 个 Unicode 字符、384 个 UTF-8 字节。
- `self.yao.get(result_id?)`：查询保留的结果，不生成随机数；不传编号取最近一卦。

内存保留最近四次完整结果，切换页面、小智重连后仍可查询，重启清空。
缓存内相同请求标识和问题重复调用，返回同一结果；同一标识搭配不同问题报错。
重复调用保护只覆盖这四条缓存，不是无限历史或持久化去重。
追问使用查询方法，找不到结果时不应自动重新起卦。

手动和语音起卦共用核心逻辑和记录。小程序活跃时由导航任务访问，
页面切换完成后由小智工作任务访问；LVGL 回调不访问记录。
返回内容包括自下而上的六爻数值、动爻编号、本卦、之卦、完整卦辞和六条爻辞（`yaoci` 数组），以及一至两段主次读原文；乾坤附加 `special` 用辞。
规则涵盖零至六个动爻以及乾坤用九、用六。

## 资源与网络

复用主题、顶部、底部提示和字幕字体，没有音频任务、动画定时器、独立 Wi-Fi
凭据或专用分区。通过已有网络任务准备射频，可在不连接网络的情况下启动已有
STA 模式，不扫描、不打开热点、不停止或释放 Wi-Fi。
随机源就绪前会报错，不使用伪随机回退。小智解读及追问需要联网。

## 验证

`tests/test_yao.c` 覆盖全部 4096 种六爻组合、64 卦、选读优先级、铜钱概率、
重复调用、随机源不可用、无效参数、结果保留和提示词构建。
`test_xiaozhi_tools.c` 还检查方法发现及不提交导航动作的返回路径。
链接核心、原文数据、服务与 cJSON，以 `BADGE_CONTROL_HOST_TEST` 注入确定性随机源。
界面渲染和真实云端解读需要与这些主机检查分开报告。

页面标题下方持续显示自动定位与校时状态。结果正文顶部显示第六爻成卦时间对应的真太阳时（网络定位近似值），下方为北京时间及完整卦爻辞，上下键可滚动浏览。定位缺失或起卦时未校时会明确提示；一小时内重新进入不会重新定位，已有成卦时间不会改变。网页配置页另行显示实时校准时间。

从小智返回时，有效经度缓存直接复用；若没有有效缓存，则释放小智保留的空闲连接，为定位请求腾出内存，避免一直停留在准备状态。当前时间、历史起卦时间和定位缓存有效期分别处理。
